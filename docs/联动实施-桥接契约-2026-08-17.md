# 联动实施 · 桥接契约 v1(2026-08-17)

> 实施依据:`docs/联动设计-dsh中枢-2026-08-17.md`(方案 B:控制面收敛 dsh,数据面留 Rust/Go)。
> 本文件是 Rust / dsh 插件 / client-nav / Vue 面板四方同时施工的唯一事实来源。
> 任何一方需要改契约,先改本文件再改代码。

## 0. 通道总览

```
dsh 嵌入运行时(starhub-agent 组合)
   │  stdio JSON-RPC 双向(已有:starhub/tool.execute、starhub/approval.request)
   ▼
Rust 主进程 ── Tauri 事件 ──► 所有 webview(主壳 client-nav + embed Vue 窗口)
   │  Tauri command(前端 → Rust)
   ▼
Vue 面板 / client-nav React 壳
```

- **dsh → Rust**:已有双向 request 模式,新增方法直接在 `handle_inbound_request` 注册。
- **Rust → dsh**:新增 **notification**(单向、无响应)。`JsonRpcLineTransport.notify()` 已存在;
  dsh 侧 sdk-jsonrpc-server 打补丁:把入站 notification 多路分发给订阅插件(新服务 `sdk-notifications`)。
- **Rust → 前端**:Tauri `emit`(广播) / `emit_to("main", ...)`(主壳)。
- **前端 → Rust**:Tauri command。

## 1. 领域事件 schema(M2/M4 共用)

```jsonc
{
  "kind": "ssh.command_executed | ssh.exec_completed | db.query_executed | db.table_opened | sftp.transfer_completed | session.attached | session.detached",
  "assetId": "a1",            // 资产 id;无资产上下文时省略
  "ts": 1724000000,           // 秒级 unix 时间戳
  "summary": "模型可读单行摘要", // 供 pre-step 注入
  "data": { },                // 领域负载:exitCode / rowCount / bytes / database / table ...
  "origin": "user | ai"       // 省略 = user
}
```

规则:
- 终端高频输出**不**逐行进事件流,只记「命令提交/完成」粒度(设计文档 §7.1)。
- `summary` 单行、≤200 字符、不含敏感值(密码/密钥一律不落)。
- AI 起源事件由 Rust 在 `starhub/tool.execute` 成功后自动生成(origin=ai);
  用户起源事件由前端面板经 `dsh_report_domain_event` 上报。

## 2. stdio JSON-RPC 方法(dsh ↔ Rust)

### 2.1 Rust → dsh notifications(新增)

| 方法 | params | 时机 |
|---|---|---|
| `starhub/registry.sync` | `{ sessions: [{ assetId, sessionId, kind: "ssh"\|"sftp"\|"db", attachedBy: string[] }] }` | 注册表每次变更(attach/detach/断线)发全量快照 |
| `starhub/domain.event` | 领域事件(§1) | 事件产生即报 |

dsh 侧:sdk-jsonrpc-server 补丁暴露 `sdk-notifications` 服务
(`subscribe(method, handler) => disposer`),插件按方法名订阅。

### 2.2 dsh → Rust requests(新增)

| 方法 | params | result |
|---|---|---|
| `starhub/live.snapshot` | `{}` | `{ sessions: [...registry], transfers: [{ id, assetId, direction, bytes, totalBytes, state }], recentExecs: [{ assetId, toolName, summary, tail, ts }], taskTrails: [{ sessionId, assetIds: string[] }] }` |
| `starhub/open.asset` | `{ assetId, tool?: "terminal"\|"sftp"\|"db"\|"auto", sessionId }` | `{ ok: true, action: "opened"\|"focused" }` |
| `starhub/focus.tool` | `{ assetId, tool: "terminal"\|"sftp"\|"db", sessionId }` | `{ ok: true, action: "opened"\|"focused" }` |

- `recentExecs`:Rust 侧缓存每个资产最近一次 AI 工具执行的摘要 + 输出尾部(≤2KB)。
- `taskTrails`(M6):每个 dsh session 的资产访问轨迹(去重保序,上限 20);
  open.asset/focus.tool 带非空 `sessionId` 时,处理器同时把该会话**重锚**到目标资产
  (复用 `dsh_bind_session` 的绑定)——编排链路里「打开 web-1 终端」之后,
  后续域工具调用自动路由到 web-1,直到锚点再次切换。
- open.asset / focus.tool:Rust emit `starhub://open-asset` 到主壳,由 client-nav 真正
  开窗/聚焦;Rust 立即返回 `{ok:true, action}`(fire-and-forget,不等待窗口就绪)。
  `action` 由 Rust 按窗口注册表预判(已有该资产窗口=focused,否则 opened)。

### 2.3 已有方法(不动)

`starhub/tool.execute`、`starhub/approval.request`、`shutdown`。


**窗口 label 约定(M5 focus 的前提)**:embed 操作页窗口 label 一律
`starhub-page-{assetId}-{tool}`(tool = terminal/sftp/db;`auto` 由 client-nav 按资产
类型解析后落地),取代原来的 `starhub-page-{Date.now()}`。capability glob
`starhub-*` 不受影响。聚焦路径:create_webview_window 同 label 冲突即说明窗口在,
转 `plugin:window|set_focus`;Rust 侧用 `app.get_webview_window(label)` 预判 action。
壳内 overlay(ssh 终端,非独立窗口)不参与 label 体系,Rust 预判不到时按 opened 报。
## 3. Tauri 事件(Rust → 前端)

| 事件 | 目标 | payload |
|---|---|---|
| `starhub://domain-event` | 全部窗口广播 | 领域事件(§1,含 origin) |
| `starhub://open-asset` | 主壳(`emit_to("main")`) | `{ assetId, tool, action: "open"\|"focus" }` |
| `starhub://ask-ai` | 主壳(`emit_to("main")`) | `{ text, assetId?, assetName? }` |

## 4. Tauri commands(前端 → Rust)

| command | 参数 | 返回 | 说明 |
|---|---|---|---|
| `dsh_report_domain_event` | `event: DomainEvent` | `()` | 用户起源事件上报;Rust 转发 dsh notify + 广播 `starhub://domain-event` 给其他窗口 |
| `starhub_ask_ai` | `{ text, assetId?, assetName? }` | `()` | 面板「问 AI」入口;Rust emit `starhub://ask-ai` 到主壳 |
| `ssh_attach` | `{ assetId }` | `{ sessionId, reused: bool }` | M1 附着:有活 session 复用(refcount+1),否则按资产存档建连 |
| `ssh_detach` | `{ sessionId }` | `()` | refcount-1;归零才真断 |

## 5. dsh 侧新插件(packages/starhub/)

| 包 | 服务 | 职责 |
|---|---|---|
| `session-registry` | `starhub-session-registry` | 消费 `starhub/registry.sync`,维护 assetId→session 视图;`list()` / `forAsset(assetId)` |
| `domain-events` | `starhub-domain-events` | 消费 `starhub/domain.event`,环形缓冲(每资产 50 条);`recent(assetId?, limit)` |
| `live-context` | (无服务,pre-step 插件) | `agent/pre-step` 注入:registry 快照 + 最近事件摘要 + `starhub/live.snapshot` pull;Config: `maxEvents`(默认 10)/ `maxSnapshotChars`(默认 4000)/ `enabled`(默认 true)。**会话级收敛(v0.140.3)**:AI 起源内容(领域事件的 `sessionId`、recentExecs 的 `sessionId`)只放行当前 agent 会话自己产生的执行——主壳会话不再看到 SSH 页助手刚跑过的命令,反之亦然;用户起源事件(终端连接/断开)是资产事实,无会话归属,全局保留 |

组合:`examples/starhub-agent/cordis.yml` 追加三插件(排在 starhub-tools 之后);
`examples/package.json`、`python/sdk-runtime/package.json`、`tsconfig.host.json` 同步。

模型工具新增(starhub-tools):`open_connection(assetId)`、`focus_terminal(assetId)`,
分别桥 `starhub/open.asset`(tool=auto)与 `starhub/focus.tool`(tool=terminal)。
非破坏性 UI 动作,approval-bridge 风险门对未列名工具默认放行,无需改门。

## 6. client-nav(React 主壳)

1. **`@` 资产 source**(ui-input-trigger 流水线):name `starhub-asset`,trigger `@`;
   candidates 来自资产快照;onPick 返回 ReferenceInsert(codec serialize →
   `<asset id="…">name (user@host)</asset>`),并**轻绑定**:写 `starhub-tool-context`
   settings namespace 的 assetId/assetName(复用现有 settings.update 通道),不切窗口。
2. **监听 `starhub://open-asset`** → openAssetPage / 聚焦已有窗口。
3. **监听 `starhub://ask-ai`** → 聚焦(或新建)会话并 prefill composer 文本,落在 DSH 原生对话视图(壳内自绘 AI 聊天面板 AiChatPanel 已移除,其 open 无写入方、本就是死 UI)。

## 7. Vue 面板

1. **「问 AI」入口**:DbView / SshTerminal / SftpView 工具栏按钮,把选中行 / 屏幕片段 /
   报错文本经 `starhub_ask_ai` 发到壳内 AI。
2. **监听 `starhub://domain-event`**(按本面板 assetId 过滤):
   - DbView:`db.query_executed`(origin=ai)→ 自动刷新当前结果网格;
   - SshTerminal:`ssh.*`(origin=ai)→ 终端上方横幅「AI 执行了 xxx」;
   - SftpView:`sftp.transfer_completed` → 刷新对应侧列表。
3. **用户起源上报**:SSH 命令提交(commandGuard 判定处)、DB 查询完成、表打开,
   经 `dsh_report_domain_event` 上报(summary 单行脱敏)。
