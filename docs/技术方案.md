## 1. 产品定位与核心价值

### 1.1 一句话定位
**"All-in-One 开发运维桌面中枢"** — 把数据库客户端、SSH 终端、文件传输、Docker 管理、AI 助手,装进同一个原生桌面应用,解决"窗口来回切"的痛点。

### 1.2 核心价值主张
| 痛点 | 现状(碎片化) | 我们的方案 |
|---|---|---|
| 工具多 | Navicat + Xshell + Portainer + 资源管理器同时开 | 一个窗口搞定所有 |
| 切换累 | 操作 A 时被 B 打断,上下文丢失 | 同屏三栏(本地/远程/编辑)、命令广播 |
| 配置散 | 资产、密钥、SQL 脚本散落各处 | 统一资产中心,云端可选同步 |
| 学习成本高 | 每个工具一套快捷键、一套逻辑 | 一套统一交互范式 |
| 智能化弱 | 各工具无 AI 协同 | 自然语言描述 → 自动拆解 → 跨工具执行 |

### 1.3 对标产品
- **海外**: Termius (SSH) + TablePlus (DB) + Lens (K8s) + Cursor (AI 思路)
- **国内**: HexHub (直接对标) + JetBrains Gateway + 1Panel (Web 版)
- **差异化**: 重点放在"AI 跨工具编排"和"国产数据库支持"

## 2. 目标用户与场景

### 2.1 用户画像

| 角色 | 使用频率 | 核心诉求 |
|---|---|---|
| **后端开发** | 每天 4+ 小时 | 连服务器看日志、查数据库、查容器 |
| **DBA / 数据工程师** | 每天 6+ 小时 | 多类型数据库管理、SQL 调优、大数据导入导出 |
| **运维 / SRE** | 每天 4+ 小时 | SSH 多服务器、批量操作、Docker/K8s 排查 |
| **全栈 / 独立开发者** | 每天 2+ 小时 | 一站式开发环境、轻量部署管理 |
| **DevOps 团队 Lead** | 每天 1+ 小时 | 资产统一管理、权限分发、审计 |

### 2.2 典型场景

1. **日常开发**: 打开应用 → 选服务器 → 终端 + 文件双栏 → 改完代码直接看日志
2. **线上排障**: AI 对话输入"查 payment-api 最近报错" → 自动 SSH 拉日志 + 查相关数据库表 + 给出建议
3. **数据迁移**: 选源库/目标库 → 选表 → 差异对比 → 一键同步结构与数据
4. **服务器管理**: 资产树分组 → 批量执行命令(查版本/打标签/拉镜像) → 结果汇总
5. **AI 辅助排障**: 截个图/贴个错误 → AI 解读 → 生成修复命令 → 一键 SSH 执行

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer 5: 表现层 (Presentation)                                  │
│  Vue 3 + Vuetify 3 / Element Plus + Pinia                      │
│  终端 xterm.js / 编辑器 Monaco+CodeMirror / 图表 ECharts       │

│  资源管理、连接池、协议适配、密钥管理                           │
```

```
│  进程 1: Tauri 主进程 (Rust)                                │

├─────────────────────────────────────────────────────────────┤

│  └── Vue 3 应用 + xterm.js + Monaco + CodeMirror            │
├─────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────┘
```

### 4.3 数据流(以"SQL 查询"为例)

```
[用户输入 SELECT * FROM users WHERE ...]
        ↓
[Vue 组件: SqlEditor]
        ↓ invoke('db:query', {connId, sql})
[Tauri IPC Bridge]
        ↓ Rust 主进程接收,转发到 Go Sidecar
[Go: DatabaseAdapter.Query(ctx, connId, sql)]
        ↓
[database/sql + pgx.CopyFrom / ... → 流式获取数据]
        ↓ 分批推送(SSE / chunked)
[Tauri 端: 收数据 → 转发到前端事件 'db:result:chunk']
        ↓
[Vue: 表格组件累加数据 → 虚拟滚动渲染]
```

### 4.4 数据流(以"SSH 命令执行"为例)

```
[用户在终端敲入 ls -la]
        ↓ xterm.js onData
[Vue 组件 → invoke('ssh:write', {sessionId, data})]
        ↓
[Rust: SSH Session 通过 russh write data]
        ↓ PTY 分配
[远端 shell 执行 → stdout/stderr 实时流]
        ↓
[Rust: 通过 tokio channel 收数据]
        ↓ emit 'ssh:data'
[Vue: xterm.js write(bytes)]
```

## 6. 模块实现思路

### 6.1 SSH 模块(Rust + russh)

**核心数据结构**:
```rust
struct SshSession {
    id: SessionId,
    handle: russh::client::Handle<Client>,
    pty_tx: mpsc::Sender<Bytes>,        // 输入通道
    output_rx: broadcast::Receiver<Bytes>, // 输出通道
    metadata: SshMetadata,
}

struct Client { /* 认证处理 */ }
impl russh::client::Handler for Client { ... }
```

**关键流程**:
1. **认证**: 密码 / 私钥(读 ~/.ssh/id_ed25519 并解析) / Agent forwarding
2. **通道打开**: `channel_open_session` + `request_pty`(列宽行数从 xterm 同步)+ `exec_command` 或 `shell`
3. **数据流**: 
   - 输入: `data` 通道 → `channel.make_writer()`
   - 输出: `channel.wait()` → emit 事件
4. **断线检测**: keepalive_interval + 超时
5. **重连**: 保存 last_session_id,失败后自动 reconnect

**难点**:
- 中文输入法: xterm.js 用 `modes` API 报告输入模式,后端不能简单按字节流转发
- ZMODEM: PTY 输出保持 `Vec<u8>` 原始字节并由 Webview 侧 `zmodem.js` Sentry 检测;协议回包走 `ssh_write_binary`,普通终端输出再以流式 `TextDecoder` 写入 xterm
- 跳板机链: 用 `tokio::net::TcpStream` 中转,或 russh 的 channel 直接转发

### 6.2 SFTP 模块

**实现**: russh-sftp 协议 / ssh2 crate(更成熟但同步)

**核心数据结构**:
```rust
struct TransferTask {
    id: TaskId,
    source: Endpoint,    // local / ssh://user@host/path
    target: Endpoint,
    bytes_total: u64,
    bytes_done: u64,
    speed: u64,          // bytes/s
    state: TransferState,
}
```

**关键能力**:
- **并发**: tokio::spawn 多任务并行
- **超时**: 每条 SSH 资产保存 `sftpTimeoutSec`，默认 30 秒、允许 5–300 秒；Rust 同时用于 SFTP 子系统通道打开和 `russh-sftp` 单次请求超时
- **启动策略**: 每条 SSH 资产保存 `sftpLaunchMode`：`auto` 先请求标准 `sftp` subsystem，失败后自动诊断常见服务端路径并仅在找到可执行程序时直接启动；`subsystem` 禁止降级；`custom` 使用用户配置的远端 Unix 绝对路径
- **真实诊断**: SFTP 建链必须等待 SSH channel request 的 `Success/Failure`，并在协议初始化期间保留远端 stderr、exit status、exit signal 与提前关闭状态；禁止把已获得的远端错误覆盖成通用 Timeout
- **可控降级**: 自动诊断只执行固定探测脚本，依次检查 OpenSSH 常见路径及 `command -v sftp-server`；自定义路径经过绝对路径、长度和控制字符校验后再做 POSIX 安全引用，不接受任意 shell 命令
- **服务端修复优先**: 推荐在 `sshd_config` 使用 `Subsystem sftp internal-sftp`；外部二进制路径异常时，客户端降级用于兼容和应急，不替代服务端配置修复
- **断点续传**: SFTP `open` + offset + append
- **跨服务器**: 中转模式(本地内存/disk 缓存)
- **大文件**: 分片(4MB/片)+ 进度事件

**连接池设计**:
```go
type ConnectionPool struct {
    mu    sync.RWMutex
    pools map[string]*sql.DB  // connId -> 标准库连接池
    pgxs  map[string]*pgxpool.Pool  // PG 专用 pgx 池
}

func (p *ConnectionPool) Acquire(ctx context.Context, connId string) (*sql.DB, error) {
    p.mu.RLock()
    defer p.mu.RUnlock()
    db, ok := p.pools[connId]
    if !ok {
        return nil, fmt.Errorf("connection not found: %s", connId)
    }
    if err := db.PingContext(ctx); err != nil {
        return nil, err
    }
    return db, nil
}
```

**PG 流式查询(pgx 一等公民)**:
```go
func (a *PgAdapter) QueryStream(ctx context.Context, connId, sql string) (<-chan Row, <-chan error) {
    out := make(chan Row, 1024)
    errCh := make(chan error, 1)
    go func() {
        defer close(out)
        rows, err := a.pgxs[connId].Query(ctx, sql)
        if err != nil { errCh <- err; return }
        defer rows.Close()
        for rows.Next() {
            row, _ := rowsToMap(rows)
            select {
            case out <- row:
            case <-ctx.Done():
                return
            }
        }
        errCh <- rows.Err()
    }()
    return out, errCh
}
```

**MySQL 流式查询(标准 database/sql)**:
```go
func (a *MysqlAdapter) QueryStream(ctx context.Context, connId, sql string) (<-chan Row, <-chan error) {
    out := make(chan Row, 1024)
    errCh := make(chan error, 1)
    go func() {
        defer close(out)
        rows, err := a.db.QueryContext(ctx, sql)
        if err != nil { errCh <- err; return }
        defer rows.Close()
        cols, _ := rows.Columns()
        for rows.Next() {
            row := scanRow(rows, cols)
            select {
            case out <- row:
            case <-ctx.Done():
                return
            }
        }
        errCh <- rows.Err()
    }()
    return out, errCh
}
```

**Sidecar 进程模型**:
```go
// Go 侧:启动后从 stdin 读 JSON-RPC,处理后写 stdout
func main() {
    log.SetOutput(os.Stderr) // 日志走 stderr,不污染 stdout 协议
    
    stdin := bufio.NewScanner(os.Stdin)
    stdin.Buffer(make([]byte, 1<<20), 10<<20) // 10MB buffer
    
    rpc := NewRpcServer()
    rpc.Register("db.query", handleQuery)
    rpc.Register("db.stream", handleStream)
    rpc.Register("db.exec", handleExec)
    // ...
    
    for stdin.Scan() {
        req := RpcRequest{}
        if err := json.Unmarshal(stdin.Bytes(), &req); err != nil {
            writeError(err)
            continue
        }
        go rpc.Handle(req) // 响应携带 request id,允许乱序返回
    }
}
```

**为什么 Go 比 Node 适合 Sidecar**:
- 单二进制 ~15MB,Node.js 运行时 + npm 驱动 ~80MB
- 启动 < 50ms,Node 200-500ms
- goroutine 处理并发连接池 / 流式天然适合,Node 单线程事件循环在 CPU 密集场景吃亏
- 跨平台编译简单(`GOOS=...` 一行),Node 需要考虑 node-gyp、原生模块

Rust 主进程将 stdin 写入与 stdout 读取拆为独立任务,使用请求 ID 映射 `oneshot` 响应通道。多个数据库请求可同时在途,默认 RPC 超时为 120 秒;Sidecar 退出时会一次性失败所有待处理请求,避免界面永久等待。启动阶段通过 `version` RPC 校验协议版本及关键方法清单,旧二进制或能力缺失会直接阻止应用启动并给出重装提示。
- 静态类型在数据库 schema 映射时编译期就能发现错误

- v0.28.10 起全局 AI 的无标签页 SSH 运行时调用 `ssh_connect_exec`,只建立认证连接并由 `ssh_exec` 按命令打开短生命周期 channel,不申请 PTY、不启动登录 shell,步骤结束后立即断开。手动终端和连接工作区内的交互 AI 仍走 `ssh_connect` + PTY;建链日志分别记录认证耗时、总耗时与连接模式。

#### 6.5.1.1 Jev 决策层(v0.123.0,Phase 1)

**形态**: 主模型每一步「从 `browser_extract` 的编号元素列表里挑下一个动作」是
封闭集判别(高频、低创造性),`browser_decide` 把它卸载给 TypeSafe「System One」
决策模型 Jev:**决策与执行分离**——Jev 只输出「动作原语 + 元素编号 + 置信度」,
不执行;执行仍由主模型调 `browser_click`/`browser_type` 等既有工具完成,审批链路
原样保留(确认卡上仍显示真实动作)。`snapshot` 参数缺省时,Rust 侧按当前引擎内部
补一次 Extract(引擎解耦,编号空间天然对齐)。

**链路**: `browser_decide{goal, snapshot?}` → `browser/decide.rs`
(settings `ai.jev.*` 读配置 + keyring `model:jev` 取 key)→
`POST {base_url}/v1/systemone`(裸 HTTP,reqwest OnceLock 客户端,不带任何会
自动追 `/chat/completions` 的 OpenAI SDK)→ `state`(目标 + 页面快照)+
`questions`(action 六原语白名单 + element 编号候选)→ 应答 `answers` 校验
(动作必须在白名单、编号必须纯数字、confidence ∈ [0,1])→ 模型可读决策文本;
confidence < `ai.jev.threshold` 时返回 `[LOWCONF]` 前缀,交还主模型兜底。

**配置与密钥**: 默认**关闭**(`ai.jev.enabled=0`);非密配置
(`base_url`/`model`/`threshold`/`timeout_ms`)走 settings 表,经新增的一对
Tauri 命令 `browser_get_jev_config`/`browser_set_jev_config` 由设置 → AI 浏览器
tab 读写;API key 走现成 keyring 命令 `set/get/delete_ai_model_api_key(id="jev")`。
设置页明文提示:**启用后页面快照与目标文本将外发至所配置端点**(默认 TypeSafe
官方 API),私有部署场景填自建/内网端点并确认合规后再开启(呼应 §1021「LLM API
不允许外发(企业版)」)。tab 内引擎与 Jev 配置共用底部唯一「保存」按钮(本地草稿,
点击才落库);API Key 保留独立的「保存密钥 / 删除密钥」(keyring 写入,与配置分离)。

**审批与审计**: `browser_decide` 显式登记进 approval-bridge
`STARHUB_DOMAIN_TOOLS`(不登记 = 风险门返回 null = 完全不确认),不加 switch
case → default ALLOW(只读,与 extract 同级);审计经 `browser_` 前缀自动命中
`browser.action` 领域事件,`goal` 已加入 `AUDIT_ARG_WHITELIST`。请求构造与响应
解析是纯函数(14 个 Rust 单测覆盖白名单/编号/置信度/HTTP 错误映射),Jev 字段级
差异被隔离在 adapter 边界内。设计与调研依据:
`docs/Jev决策模型-浏览器操作接入调研.md`。

#### 6.5.1.2 browser_auto 连续执行循环(v0.126.0,Phase 2)

**形态**: 第 16 个 `browser_*` 工具。主模型一次调用,Rust 内部循环
extract → Jev decide → 执行,汇总返回——Phase 1「每个动作都要主模型一次完整
round-trip」的瓶颈由此收进一次工具往返。参数:`goal`(必填)、`max_steps`
(默认 8,钳制到 `ai.jev.auto_max_steps`)、`stop_on_lowconf`(默认 true)、
`input_text`(type 步骤的键入文本)、`snapshot`(可缺省,内部自取)。

**循环**(`src-tauri/src/browser/auto.rs`,引擎解耦): 每步新鲜 Extract
(`script::DEFAULT_MAX_CHARS`)→ `decide::decide_struct()`(与 browser_decide
共用客户端;每步重读配置,中途关 Jev 即软错误中断,fail loud)→ 低置信度且
`stop_on_lowconf` → `[LOWCONF]` 中断交接 → `done` 收口 → 防震荡(同一页面
同一决策重复,即上一步没有产生页面变化)→ 白名单原语执行
(click/type/scroll/press_key)。**能力划界**:Jev 不生成自由文本——`type` 需
调用方提供 `input_text`,`select_option` 一律 `[HANDOFF]` 交还主模型。汇总含
每步(动作/元素/置信度/结果)与终止原因,总截断 8000 字符(仿 browser_eval);
软错误(元素失效等)带已执行摘要中断。

**JevGate 交互**: `browser_auto` 进 `JEV_REVOKING_TOOLS`(页面必变)、**不进**
`JEV_GATED_ACTIONS`(循环自决策,进门即死锁);循环内 decide 不过桥,不授不耗令牌。

**步数上限**: settings `ai.jev.auto_max_steps`(默认 50、区间 1–500,设置 →
AI 浏览器可改);模型传参超过时按上限执行,汇总首行披露实际上限。配置随
`JevConfig`(字段 `autoMaxSteps`)走 `browser_get_jev_config` /
`browser_set_jev_config`,validate 增区间校验。

**审批与授权态**: approval-bridge 对 `browser_auto` 软 ask(「一次确认授权
循环内全部步骤;确认后 N 分钟内本会话的后续 browser_auto 不再逐一确认」);
循环内步骤不经桥、继承本次确认(与 Android 设备上的任务级授权同构)。定时授权
`autoGrantActive()` 从会话日志的 `approval/asked` + `approval/decided` 审计对
派生(`ApprovalService.request()` 自写,与 answerer 配置无关;无状态、可重放),
TTL 为插件 Config `autoGrantMinutes`(默认 10 分钟,cordis.yml 可配)。授予只
抑制确认卡,爆炸半径仍由步数帽死。

**可观测**: 每步决策落 `Jev 决策` info 行(action / element / confidence /
elapsed_ms;starhub.log grep 可还原整条自动轨迹);`browser_` 前缀自动命中
审计与 `browser.action` 领域事件,一行审计 = 一次 auto 调用。立项设计与机制
选型:`docs/browser_auto-连续执行循环-立项设计.md`。

**可观测性与调用方式(v0.123.4 补,v0.124.0 改为强制)**: 启用 Jev 决策
(`ai.jev.enabled=1`)后为**强制模式**(v0.124.0 起):主模型的每个页面动作
(`browser_click`/`browser_type`/`browser_scroll`/`browser_press_key`/
`browser_select_option`)执行前必须先调 `browser_decide` 拿到一次新决策,
否则动作在执行层被拒(软错误,提示先决策);一次动作一次决策,页面变化类工具
(`browser_navigate`/`open`/`back`/`forward`/`reload`/`extract`/`eval`)自动
吊销旧决策。实现是 `browser/mod.rs` 的会话级「决策令牌」状态机
(`JevGate`:decide 成功授予 → 动作消费 → 页面变化吊销),Jev 未配 key/端点
不通时动作门保持关闭(fail loud),关闭开关即整体退回按需模式。核对「某次
任务有没有走 Jev」有双通道——`starhub.log` 里 `decide()` 完成时写的
`Jev 决策` info 行(action / element / confidence / elapsed_ms),以及审计表
AI 类别 action=`browser_decide` 的明细行(goal / durationMs / success /
error)。`ai.jev.base_url` 缺省为官方端点 `https://api.typesafe.ai`
(v0.123.4 修:此前 Rust 默认空串会被前端 `{...JEV_DEFAULT, ...value}` 展开
成全空字段,启用后 `browser_decide` 必然软失败;空值库读取时自动自愈)。

**安全边界**: webview 后端 `capabilities/browser.json` 只给 `ai-browser` 窗口
(任意 http/https origin)放行 `browser_internal_result` 一条命令;导航协议白名单
http/https/about:blank(拒绝 javascript:/file:/data:);无痕 profile 不落 Cookie。
obscura 后端为无头引擎,页面不经过 Tauri IPC,由 CDP 命令白名单收窄;`obscura-live://`
查看器窗口不匹配任何 capability,零命令权限。

**关窗联动**: 主窗口 CloseRequested 时销毁其余全部窗口
(detach-*/ai-browser/screenshot-overlay/obscura-live-*),杜绝孤儿窗口;ai-browser
销毁时在途 eval 立即失败收口;主窗口 Destroyed 时 `obscura::shutdown` 回收无头
引擎进程。

**空闲自动关闭(v0.123.3)**: webview 引擎的 `ai-browser` 窗口连续 60s
(`browser/idle.rs` `IDLE_CLOSE_SECS`)没有新的 `browser_*` 调用、且无在途调用与
在途 eval 时,由 setup 启动的看门狗(5s 轮询)自动关闭;关闭走与用户手动关闭同一
条路径(Destroyed 时在途 eval 失败收口),下一次 `browser_open`/`navigate` 重建
窗口(页面状态不保留)。活动时刻与在途计数挂在 `BrowserManager`:每次桥调用
`begin_call()` 刷新时刻并持计数(返回的守卫 panic / 提前返回也递减)。obscura
引擎(进程 + 直播查看器窗口另一套生命周期)暂不适用。

### 6.5.2 Android 实体机(adb 直连,v0.107.0)

**设计文档**: `docs/superpowers/specs/2026-08-30-android-device-design.md`。

**通道选择**: AI 直操作用户真实手机走 adb(Android Debug Bridge)——
比容器方案(redroid/docker-android 依赖 KVM,Docker Desktop on Windows 不可用)、
代理 APK 方案(能力子集)覆盖面全、零内核改造(v0.132.0 起沙箱桌面已整体退役,
设备直连是唯一的 AI 操作通道)。

**Rust `android` 模块**(`src-tauri/src/android/mod.rs`,不经 sidecar——
adb 自身就是设备代理,主进程 spawn `adb` 子进程即可):

- adb 二进制四级解析:settings `android.adb_path`(设置页可配)→
  环境变量 `STARHUB_ADB_PATH` → PATH → 平台常见安装位置;全部缺失时报错带
  三平台安装引导(winget/brew/apt),AI 可用本机工具代装;不做自动下载
  (供应链风险)。
- **20 个 `android_*` AI 工具**(tools 插件桥接,approval-bridge 分级):
  发现(list_devices)/授权连接(connect,一次确认 = 60 分钟任务级授权,
  serial 匹配与过期由 Rust 执行点强制)/断开/状态/回放/无线调试封装
  (wireless,配对码只能用户从手机读取)/截图回灌(screenshot → read_image)/
  前台感知(current_app)/**界面树(ui_tree,v0.109.0:`uiautomator dump` 落
  `/data/local/tmp/starhub/` 后 base64 回传——免疫 exec-out CRLF 损坏;解析
  出可点击/有文字节点的中心坐标(物理像素)直喂 android_tap,结构化坐标
  免读图估算;shell 权限即可,不需要手机开无障碍服务;锁屏/FLAG_SECURE
  安全页/自绘画面返回空并提示回退截图)**/触控
  (tap/double_tap/swipe/scroll)/文本输入
  (type:ASCII 走 `input text`,非 ASCII 走 ADBKeyBoard 广播,未装给引导)/
  按键白名单(press_key → KEYCODE_*)/按包名启动(launch_app)/直播开窗
  (open_live)/文件传输(pull/push,远端目录白名单 /sdcard、/data/local/tmp)/
  万能钥匙 exec(恒确认 hard 档,never 预设也不静默)。
- **直播双模**(`android-live://` custom protocol,窗口 label 不匹配任何
  capability,页面无 app command 权限):
  - scrcpy 模式:bundled scrcpy-server v2.7(SHA256 钉死,PROVENANCE.md
    记录来源/校验/升级步骤)推送到设备 `app_process` 启动,H.264 经
    `adb forward tcp:P localabstract:scrcpy` 回本机;GOP 环形缓冲按 since
    偏移增量供给,直播页 WebCodecs `annexb` 解码(~12fps);
  - 轮询兜底:pump 周期 `exec-out screencap`,页面轮询 frame.png
    (~1.5fps),无 WebCodecs 的 webview 自动走这条。
  - 接管输入经 mpsc → pump → `adb shell input`(scrcpy 控制通道未启用);
    接管开启期间 AI 写操作一律拒绝(不撤销授权);窗口销毁自动停泵 +
    杀 server + 解除 forward。
- **回放留档**:每次写操作前自动截屏(`android_replay_frames` 表,
  `android_replay` 可查);`android_type` 文本不进审计(只记长度)。
- **截图坐标契约(v0.108.0 修正)**:截图落盘为设备物理分辨率 PNG,
  `android_screenshot` 结果直读 PNG IHDR 注明当次真实 `宽x高`(不信任
  connect 时缓存的 `wm size`——横竖屏切换/改分辨率都免疫);坐标类工具
  (tap/swipe 等)一律吃物理像素,read_image 缩图时模型按其结果注明的
  `multiply coordinates by k` 换算。工具描述同步写明这套换算规则。
- **UI 命令**(工具面板「Android」子类 + 设置页):`android_ui_get_config` /
  `android_ui_set_adb_path`(adb 路径配置)、`android_ui_list_devices`
  (adb 设备列表,只读免授权)、`android_ui_open_live`(面板按钮直开直播
  窗口,用户点击 = 审批表达;分辨率现场探测,与 AI 路径共用
  `open_live_window`)。设备写操作仍只走 AI 工具路径。

**工具面板「Android」子类**(v0.108.0):侧栏工具面板的 Android 子类
(`STARHUB_SUBCATEGORIES` key=`android`,`matches()` 恒 false——设备不是
资产),展开渲染 `AndroidPanel`(adb 设备卡片:型号/serial/状态徽标 +
「打开直播」),由 `StarHubToolWorkspace` 对无资产子类特判渲染。

**已知坑**(详见 `docs/踩坑记录.md`):旧版 adb(<1.0.41)exec-out 的
CRLF 二进制损坏按「k 个 \r+\n → k-1 个 \r+\n」修复(PNG 8 字节 magic 自身
含 \r\n,是现成探针);`input text` 先转 input 层(%→%%、空格→%s)再
sh 单引号;unauthorized 状态引导用户在手机上点「允许」;scrcpy server 首参
必须等于自身版本号。

### 6.5.3 SSH 终端 AI 助手(v0.134.0)

**形态**:SSH 终端页(starhub-window 的 `SshTerminalOverlay`)第三个页签
「AI」——右侧助手面板,操作**这台已连接的服务器**,模型连接复用 dsh 的
部署默认(`agentDefaultModel`,即设置里配的 provider/key/model),面板顶部
可临时切换(仅本助手后续请求生效,`agent/request` 瀑布替换冻结的 call
config,路由变更时丢掉过期 reasoningEffort)。

**宿主插件 `starhub-ssh-assistant`**(第十个 StarHub 包,注入
`['agents','webServer','tools','llm']`):

- **一会话一助手**:`ctx.agents.create()` 建根 Agent(sessionId =
  `ssh-assistant-<uuid>`),按终端页会话 id 幂等(重进页复用);关页面/插件
  卸载 → `handle.dispose()`,会话不在后台常驻;
- **会话归组(v0.140.2)**:助手会话的 cwd 取**默认工作区**
  (`workspaceRegistry` 里标题为 `default-workspace` 的工作区,GUI 显示为
  「默认工作区」)的规范路径,建会话后经 `attachSession` 记入该工作区
  账户——dsh 会话列表按「账户里有该会话 + 会话头 cwd 等于工作区路径」
  双条件归组,助手对话因此列在工作区分组下(v0.140.2 之前打 StarHub 自有
  目录 `~/.starhub/ssh-assistant`,落「未分组」)。没有默认工作区(被用户
  改名/删除,或组合里没有 workspace 家族)时回落自有目录(Config
  `sessionCwd`),行为同旧版;注册表尚未就绪或 attach 被拒(工作区目录
  漂移)只告警,不打断助手打开;
- **工具面收敛**:creation window 里 `agentCtx.tools.restrict({allow})` 到
  8 个 SSH/SFTP 工具(ssh_exec / ssh_exec_background / ssh_wait_task /
  ssh_session_status / sftp_list / sftp_stat / sftp_upload / sftp_download)——
  本地 shell、数据库、浏览器、其它服务器对助手不可见;
- **资产绑定**:经桥 `starhub/bind.asset` 把助手会话绑到该资产,sidecar
  `resolve_asset_id` 自动路由;
- **连接模型(v0.140.0 重写,v0.140.1 页面级化)**:AI **不自建连接**——
  `resolve_user_session` 按资产解析用户终端页已连接的会话(`ui.ssh_connect`
  下发 `assetId`),命令在用户的同一条 shell 上执行:普通主机走同一
  连接的 exec 通道(不打扰用户终端),堡垒机类资产把命令写入用户终端的 pty
  (用户在里面亲手完成 MFA 与选机器;输出经 pty tap 哨兵回采,用户在终端里
  可见)。**页面级复用(v0.140.1)**:助手打开时经 `starhub/bind.asset` 把
  所在终端页的会话 id(`terminalSessionId`)一起绑定,域工具优先复用**那个
  页面**的连接(`SshManager::alive_session_for` 校验存活与归属);该页没有
  活连接才回落同资产第一个存活会话(主壳 AI 无页面上下文,直接走这条),
  `ssh_session_status` 页面级命中时明说「本终端页的连接」。未连接时工具
  返回「请先连接」引导文案,由模型转告用户;连接级失败不再自动重连
  (连接归用户,断了由用户在终端里重建);
- **权限模型**:AI 自主执行限只读命令;任何修改/删除/安装/重启,AI 以文本
  给出命令等人来跑或明确交回(「run this: …」),审批卡(写/风险恒 ask)就是
  人工交回点;
- **人设**:agent 作用域 systemPrompt section(影藏 deployment persona 槽),
  写明「复用用户连接、没连就提示去连、自主只读、写操作交回人工、没有其它
  工具」;
- **驱动面**:同源 `/starhub/api/assistant/*`(open/prompt/stop/close/model/
  approval/models + SSE stream)。SSE 转发助手会话的 durable log
  (user/message、assistant/message、tool/call、tool/result)加 status/model/
  approval/closed 帧;晚到客户端(重开页签/断线重连)先收历史重放,挂起中的
  审批卡重推;
- **审批**:助手会话的 `approval/request` 由本插件 prepend 承接——SSE 推卡、
  面板 POST `allowed-once`/`rejected`;面板没在流上时交回链尾(壳内审批 UI
  不变)。风险分级仍归 approval-bridge 风险门(只读放行、写/风险 ask)。
- **连接验证卡退役(v0.140.0)**:AI 不持有连接,`ssh:kb-interactive` /
  `ssh:bastion-*` / `ssh:hostkey-confirm` 对 AI 连接不再发生——MFA/堡垒机
  选机器/主机密钥提示只属于用户自己的终端页(SshTerminalOverlay 与壳内卡
  原位服务)。助手面板的连接卡渲染、`active-conns` 路由与壳内
  StarHubConnCard 一并移除;AI 命令的执行遥测(`ssh:exec-done`,sessionId =
  终端会话 id)仍进壳内「SSH 执行记录」视图。

**客户端**(client-nav):`assistant-service.ts`(路由客户端 + SSE 订阅)、
`assistant-messages.ts`(帧 → 聊天项纯折叠,按消息/call id 幂等)、
`SshAssistantPanel.tsx`(消息流/工具卡/审批卡/模型选择器/停止按钮);
overlay 持 assistantId 引用,卸载时销毁。

**已知限制**:模型选择器只列已注册的 provider 路由;同一资产开两个终端页 =
两个独立助手会话;助手命令走**打开它的那个终端页**的连接(v0.140.1),该页
没有活连接时回落同资产第一个存活会话,没有按命令任意选窗口的能力。

## 7. 数据模型与本地存储

### 7.1 本地 SQLite Schema(简化)

```sql
-- 资产分组
CREATE TABLE asset_groups (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id INTEGER,
  icon TEXT,
  sort_order INTEGER,
  created_at INTEGER
);

-- 资产(连接)
CREATE TABLE assets (
  id TEXT PRIMARY KEY,         -- UUID
  type TEXT NOT NULL,           -- ssh / db / docker / redis
  name TEXT NOT NULL,
  group_id INTEGER,
  config_json TEXT NOT NULL,    -- 序列化配置
  key_id TEXT,                  -- 关联密钥表
  tags TEXT,                    -- JSON 数组
  favorite INTEGER DEFAULT 0,
  last_used_at INTEGER,
  created_at INTEGER,
  updated_at INTEGER
);

-- 密钥
CREATE TABLE keys (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL,           -- password / private_key
  encrypted_data BLOB,          -- 加密后的密钥
  keyring_ref TEXT,             -- 系统 Keyring 引用
  fingerprint TEXT,
  created_at INTEGER
);

-- 快捷指令
CREATE TABLE snippets (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  group_id INTEGER,
  command TEXT NOT NULL,
  description TEXT,
  variables TEXT,               -- JSON
  scope TEXT,                   -- ssh / db / global
  created_at INTEGER
);

-- SQL 历史
CREATE TABLE sql_history (
  id INTEGER PRIMARY KEY,
  conn_id TEXT,
  sql TEXT,
  executed_at INTEGER,
  duration_ms INTEGER,
  rows_affected INTEGER,
  success INTEGER
);

-- 监控告警规则
CREATE TABLE monitor_rules (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  target_type TEXT,             -- ssh / docker
  target_id TEXT,
  metric TEXT,                  -- cpu / mem / disk
  operator TEXT,                -- > / < / ==
  threshold REAL,
  duration_sec INTEGER,
  channels TEXT,                -- JSON: webhook/email/...
  enabled INTEGER DEFAULT 1
);

-- 通用设置
CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT,
  updated_at INTEGER
);
```

### 7.2 加密策略

| 数据 | 加密方式 |
|---|---|
| 私钥 | 系统 Keyring |
| 密码 | 系统 Keyring |
| AI API Key | 系统 Keyring |
| 资产配置 | SQLite 仅存非敏感字段与 Keyring 引用 |
| 同步上传 | 端到端加密(libsodium) |
| 本地数据库文件 | 可选 SQLCipher |

Windows Credential Manager 的 credential blob 对 UTF-16 编码长度有限制。资产密钥超过安全阈值时使用带版本清单的分代分片存储;写入新分片成功后再原子切换清单,读取兼容旧版单条 JSON,更新/删除时清理旧分片。Linux 优先写入桌面 Secret Service 以跨重启持久化,仅在无桌面密钥环的 headless/WSL 环境回退到会话级内核 Keyutils。私钥正文仍只存在系统 Keyring,不会回落到 SQLite 或普通文件。

## 8. 安全设计

### 8.1 信任边界

```
┌────────────────────────────────────────────┐
│  不可信边界: 远程服务器、LLM API           │
│  - SSH 主机指纹验证                        │
│  - 数据库 SSL/TLS                          │
│  - Docker TLS                              │
└────────────────────────────────────────────┘
            ↕ 加密通道
┌────────────────────────────────────────────┐
│  半可信边界: WebView 渲染进程              │
│  - 严格 CSP                                │
│  - Tauri 权限白名单(只 expose 必要 API)   │
│  - DOMPurify 防 XSS                        │
└────────────────────────────────────────────┘
            ↕ IPC(参数校验)
┌────────────────────────────────────────────┐
│  可信边界: Rust 主进程 / Go Sidecar        │
│  - 所有 invoke 参数 zod 校验               │
│  - 危险命令二次确认                        │
│  - 审计日志                                │
└────────────────────────────────────────────┘
```

### 8.2 关键安全措施

1. **Tauri 权限最小化**: `tauri.conf.json` 中只注册必要的 plugin,command 显式声明
2. **CSP**: `default-src 'self'`,禁止 inline script
3. **输入校验**: 所有 IPC 参数 zod schema 校验
4. **密钥保护**: 密码、私钥与 AI API Key 不落盘明文,只存 Keyring 引用;长私钥按 UTF-16 安全预算分片并保留旧格式读取兼容
5. **危险拦截**: 终端侧检测 `rm -rf /`、`dd if=`、`mkfs` 等
6. **审计**: 所有"写"操作记入审计日志,带时间戳/用户/目标
7. **更新安全**: Tauri Updater 验证签名

## 10. 跨平台打包与发布

### 10.1 平台支持

| 平台 | 最低版本 | 打包格式 |
|---|---|---|
| Windows | Win 10 (1809+) | .msi 安装版 / 便携 .exe |
| macOS | macOS 11 Big Sur+ | .dmg(arm64 + x86_64) |
| Linux | glibc 2.39+（Ubuntu 24.04 / Debian 13 / Fedora 40+） | .AppImage / .deb / .rpm（x86_64 + ARM64） |
| Linux 兼容版 | glibc 2.35+（Ubuntu 22.04 / Debian 12 / Fedora 38+） | .deb / .rpm（x86_64，无截图，`-ubuntu2204` 后缀） |

Linux 默认发布固定在 Ubuntu 24.04 原生 x86_64 / ARM64 runner 构建。AppImage 随包携带 WebKitGTK、GTK 与静态 Go sidecar,作为主流 glibc 桌面发行版的通用包;DEB/RPM 通过包元数据声明系统运行库。每个产物必须通过 `scripts/verify-linux-bundles.sh`,确认架构、sidecar 可执行权限与静态链接、包依赖以及主程序 `ldd` 无 `not found`;Alpine(musl)和无 FHS 兼容层的 NixOS 不在直接兼容范围。**截图功能依赖系统 PipeWire ≥ 1.0(Ubuntu 24.04 及以上)**:截图栈 xcap → pipewire/libspa 0.10.1 需要新版 spa 头,Ubuntu 22.04(0.3.48)连绑定都无法生成,旧系统上点击截图由主进程预检后提示升级,不做静默失败。

为兼容 Ubuntu 22.04 等旧桌面发行版,截图栈整体 gate 到 Cargo `screenshot` 特性(默认开启):`linux-legacy-2204.yml` 在 `ubuntu-22.04` 原生 runner 上以 `--no-default-features`(关截图)构建,不引入 xcap/pipewire 链,产物 glibc 下限回到 2.35,文件名带 `-ubuntu2204` 后缀随 tag 附到同一 Release;代价是该兼容版不含内置 AI「区域截图」(该入口已在 v0.133.4 随去 Tauri 化 M2 一起移除,见 G-18)。
