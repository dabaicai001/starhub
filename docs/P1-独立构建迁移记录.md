## 1. 做了什么

StarHub 的全部自有源码与构建链迁出 `vendor/deepseek-harness`，改用**自己的 pnpm workspace + 官方已发布 npm 包**编译；vendor 里只剩上游本体（P3 才删）。

| 迁移项 | 原位置 | 新位置 |
|---|---|---|
| 10 个内置插件 | `vendor/.../packages/starhub/*` | `packages/starhub/*` |
| `dsh-client-runtime` 兼容垫片 | `vendor/.../packages/client/runtime` | `packages/shims/client-runtime` |
| React 工作台 app | `vendor/.../apps/starhub-window`（`@deepseek-ai/starhub-window`） | `apps/starhub-workbench`（`@starhub/workbench`） |
| profile 组合模板 | `vendor/.../examples/starhub-{desktop,web,agent}` | `profiles/starhub-{desktop,web,agent}` |
| 构建入口 | vendor 的 `tsconfig.host/client.json` + `tsdown` 预设 | 根 `tsconfig.{base,base.client,host,client}.json` + `scripts/build-client-bundle.mjs` |

新增/替换的构建件：

| 文件 | 作用 |
|---|---|
| `pnpm-workspace.yaml` | `packages/*/*` + `apps/*`；只装 StarHub 包与官方 `@deepseek-ai/dsh-*` |
| `.npmrc` | `node-linker=hoisted`（原因见 §4） |
| `scripts/build-client-bundle.mjs` | 客户端半边打包（esbuild + CSS Modules 作用域化 + 样式内联 + `__ModuleLoader__.load` 包装） |
| `scripts/clean-lib.mjs` | 替代 `clean-vendor-starhub.mjs` |
| `scripts/build-window.mjs` | 改用 Vite Node API 构建工作台（不依赖 pnpm bin 布局） |

删除：`vendor/.../scripts/fix-starhub-exports.mjs`（迁移后包清单自己就是对的）、`scripts/clean-vendor-starhub.mjs`。

## 4. 踩到的坑（给后续阶段留档）

1. **`TS2742`：声明文件里出现 pnpm 虚拟存储真实路径。** `tool-context` 的 `Config` 用 `.volatile()` 链推导类型，隔离安装下 tsc 想把 `node_modules/.pnpm/@deepseek-ai+cosmokit@1.9.0/...` 写进 `.d.ts`。显式标注 `Schema<Config>` 会撞上 `Volatile<string>` 与 schema 裸值不兼容，绕不过去；最终用 **`node-linker=hoisted`**（`.npmrc`）让真实路径就是 `node_modules/@deepseek-ai/cosmokit`，一条代码都不用改。
2. **pnpm 提升安装下的 `.bin` 不可靠。** 包级 `node_modules/.bin/vite` 指到不存在的 `node_modules/vite/bin/vite.js`，`pnpm --filter … build` 直接 ENOENT。工作台构建改成 Vite 的 Node API（`scripts/build-window.mjs`），不再依赖 bin 布局。
3. **`@types/node` 要逐包声明。** pnpm 隔离/提升安装都不会把根 devDependency 送到子包的 `types` 解析面，12 个包逐个补 `@types/node` 才过 `types: ["node"]`。
4. **Vite 5 的 esbuild 不认 `target: es2024`。** tsc 面保持 es2024，Vite 侧显式 `esbuild.target/build.target = es2022`。
5. **CSS 半边要自己实现。** 上游客户端 bundle 把 `*.module.css` 变成「作用域化类名 + 运行期 `<style>` 注入」的 JS 模块（`\0dsh-css` 插件）。自建 `build-client-bundle.mjs` 用 esbuild 原生 `local-css` loader 拿到同样效果（类名哈希不同，属实现细节），并把汇总 CSS 以 `data-dsh-css="<包名>/styles"` 去重注入。
6. **`examples/` 目录搬家后，provisioning 测试的「假树」也要跟着改。** 该测试伪造一棵「StarHub 根」并跑真脚本，布局变了但语义不变（`--vendor` 现在是「StarHub 仓库根」）。
